## 二、git 不在 PATH 上（最容易踩）

这台机器 `git` 没进 PATH，但好几处又需要它：

| 使用方 | 怎么拿到 git |
|---|---|
| `dsh-ide-git` 插件 | **只认**环境变量 `DSH_IDE_GIT_BIN`（不读 PATH，也不读 profile 的 row config） |
| `dsh-session-sync` | 读 profile row 的 `gitBin`（默认注释掉），否则也用 PATH |
| 本仓库脚本 | `scripts/common.ps1` 的 `Find-Git`：`DSH_SYNC_GIT` → PATH → PortableGit → Fork 内置 → 常见安装路径 |

本机实际可用的 git：
```
C:\Users\tanyu\.workbuddy\binaries\PortableGit\versions\1.2.0\cmd\git.exe   # PortableGit
C:\Users\tanyu\AppData\Local\Fork\gitInstance\2.50.1\cmd\git.exe            # Fork 自带
```
`setup.ps1` 会自动把找到的路径写进用户环境变量 `DSH_IDE_GIT_BIN`。

## 三、`~/.dsh/.env` 的陷阱

**`DSH_IDE_GIT_BIN` 绝对不能写进 `~/.dsh/.env`**，哪怕值是空字符串。dsh 0.2.0-rc.2 会直接致命报错：

> `dsh: ...\.env sets "DSH_IDE_GIT_BIN", which only the launching environment may set ... export DSH_IDE_GIT_BIN instead of putting it in a .env file`

正确做法：写进**用户级 Windows 环境变量**（`[Environment]::SetEnvironmentVariable(..., 'User')`），新启动的 DSH 进程自动继承。

本机 `.env` 现在是 8 行注释、0 个有效键——就是被这个问题清空的。

## 四、profile 目录里哪些文件是真的源

`~/.dsh/profiles/desktop/` 下有大量 `.bak-*`。真正生效的只有：

| 文件 | 要不要同步 | 说明 |
|---|---|---|
| `package.json` | ✅ 同步（模板化） | 插件清单 + `link:` 依赖，**这是 bundle 列表的唯一来源** |
| `cordis.patch.yml` | ✅ 同步（模板化） | 用户 patch 层：主题、模型、浮窗、宠物、provider |
| `pnpm-lock.yaml` | ❌ 不同步 | 含本机 `link:` 绝对路径，换机必失效；重新 install 会重写 |
| `pnpm-workspace.yaml` | 🔸 可选 | 内容和平台无关，但很少改 |
| `cordis.yml` | ❌ 不同步 | 恒为 `[]`，profile 恢复会重写它 |
| `compatibility.json` | ❌ 不同步 | 恒为 `{}` |
| `*.bak-*` | ❌ 不同步 | 噪音，DSH 自己产生的备份 |

**DSH 有个恢复机制会重写 `cordis.patch.yml`**（历史上发生过一次，原内容被移到 `.bak-1792142479700`）。
所以仓库里那份模板就是你的安全网——被重写后 `capture-profile.ps1` 对不上，就手动比一下，或者直接 `setup.ps1 -Force` 覆盖回来。

## 七、编辑器编码坑（写脚本时务必注意）

| 场景 | 结论 |
|---|---|
| `.ps1` 脚本含中文 | **必须存成 UTF-8 with BOM**，否则 Windows PowerShell 5.1 按 ANSI(GBK) 读会乱码并报语法错 |
| `.yml` / `.json` 配置 | UTF-8 **无** BOM（YAML/JSON 带 BOM 会解析失败） |
| 用带 BOM 的 UTF8 写 JSON | 会写出 BOM，别这么干；统一 `UTF8Encoding($false)` |

本仓库 `scripts/*.ps1` 全部是 UTF-8 BOM，`config/**` 全部是无 BOM UTF-8。改动时别弄反。

## 八、已知的历史坑（脚本里都处理了）

| 现象 | 原因 / 处理 |
|---|---|
| `dsh-image-gen` 装完不生效 | 依赖 `link:` 指向的源码路径，先还原 `package.json` 再 install |
| `git add` 满屏 "LF will be replaced by CRLF" | 全局 `core.autocrlf=true`。仓库内已设 `core.autocrlf=false` + `.gitattributes` 统一 LF |
| 中文路径在 cordis 里加载失败 | 必须用百分号编码的绝对 `file://` URI（`@COMPONENT_URI@`） |
| DSH 启动报 `.env sets DSH_IDE_GIT_BIN` | 见第三节，改用用户环境变量 |
| profile 恢复把 `cordis.patch.yml` 清空 | 见第四节，仓库模板是安全网 |

## 九、常用路径速查

```powershell
# DSH 安装目录（注册表里读）
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*' |
  Where-Object DisplayName -like 'DeepSeek Harness*' | Select-Object InstallLocation

# 直接用 CLI（不依赖 PATH）
& '<安装目录>\resources\runtime\cli\bin\dsh.cmd' --version
& '<安装目录>\resources\runtime\cli\bin\dsh.cmd' plugin --profile desktop install

# 校验 profile 组合结果
& '<安装目录>\resources\runtime\cli\bin\dsh.cmd' --profile desktop --dump-config
```

`dsh plugin` 会写 `~/.dsh/profiles/desktop/package.json.lock`，在沙箱里跑会 EPERM——那是权限问题，不是命令用错了。
